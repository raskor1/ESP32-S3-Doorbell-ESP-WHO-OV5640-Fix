# Умный домофон на ESP32-P4 + ESP32-S3

Этот репозиторий содержит код и историю разработки автономного умного домофона с распознаванием лиц. Проект состоит из двух плат, работающих в локальной Wi-Fi сети без выхода в интернет.

## 🏗 Архитектура проекта

1. **Монитор (Дом) — ESP32-P4 (Guition JC1060P470C)**
   - 7-дюймовый экран 1024x600, LVGL 8.4.
   - Создает точку доступа Wi-Fi.
   - Принимает видеопоток (MJPEG) с уличной камеры.
   - Управляет реле замка.
   - Плавающие часы, интерфейс звонка, таймеры бездействия.
   - Код находится в папке `01_P4_Monitor`.

2. **Камера (Улица) — ESP32-S3 N16R8 CAM**
   - Камера OV5640 (DVP интерфейс).
   - Подключается к сети P4 как клиент.
   - Отдает видеопоток по HTTP (MJPEG) на порт 81.
   - Код находится в папке `02_S3_Camera_Stream`.

## 🛑 Проблема с распознаванием лиц (ESP-WHO + OV5640)

Изначально планировалось запустить распознавание лиц (ESP-WHO) прямо на уличной камере (ESP32-S3). Однако мы столкнулись с серьезными аппаратными ограничениями:

1. **Разрешение 800x600**: Драйвер `esp_video` поддерживает OV5640 на DVP-интерфейсе только в разрешении 800x600 (SVGA). Меньших разрешений (640x480 или 320x240) в `menuconfig` просто нет.
2. **Нехватка памяти и переполнение шины**: Кадр 800x600 в RGB565 занимает ~960 КБ. При попытке выделить несколько буферов для DMA (минимум 3 для ESP-WHO) память забивается, а пропускной способности шины не хватает для потока. Плата уходит в бесконечную перезагрузку `rst:0xc (RTC_SW_CPU_RST)`.
3. **Brownout**: В момент старта камеры и DMA происходит скачок потребления, вызывающий сброс по питанию.

### 💡 Решение
Замена камеры на **OV2640**, которая поддерживает разрешение **QVGA (320x240)**. Это снижает вес кадра в 9 раз, избавляет от проблем с DMA и позволяет комфортно запустить нейросеть.

## 📂 Структура репозитория
- `/01_P4_Monitor` — Исходный код монитора (ESP-IDF, C, LVGL).
- `/02_S3_Camera_Stream` — Исходный код камеры (ESP-IDF, C, MJPEG сервер).

## 🛠 Используемые технологии
- **ESP-IDF v5.x / v6.0**
- **LVGL 8.4** (графика на P4)
- **esp32-camera / esp_video** (работа с сенсорами)
- **HTTP/MJPEG** (передача видео)
- **ESP-WHO / ESP-DL** (попытка интеграции нейросетей)

# ESP32-S3 Doorbell: ESP-WHO + OV5640 Debugging

Этот репозиторий — документация и код нашего пути по созданию умного домофона на ESP32-S3 с распознаванием лиц (ESP-WHO) и камерой OV5640.

## 🛑 Проблема (The Problem)
При попытке запустить пример `human_face_recognition` из ESP-WHO на плате ESP32-S3 (N16R8) с камерой OV5640 возникала ошибка:
`rst:0xc (RTC_SW_CPU_RST)` — бесконечная перезагрузка.

### Найденные "грабли":
1. **Разрешение 800x600 (SVGA)**: Драйвер `esp_video` для DVP-интерфейса на ESP32-S3 поддерживает OV5640 только в разрешении 800x600. В `menuconfig` нет вариантов 640x480 или 320x240.
2. **Переполнение памяти**: Кадр 800x600 в формате RGB565 весит ~960 КБ. При запросе 3+ буферов для DMA драйверу не хватает внутренней RAM (Internal RAM), а PSRAM DMA по умолчанию может быть выключен.
3. **Ошибка `ringbuf_len >= 1`**: В ESP-WHO жестко зашито, что количество буферов камеры (`fb_count`) должно быть **минимум 3**. Установка значений 1 или 2 вызывает `assert` и падение.
4. **Brownout (Просадка питания)**: При старте камеры и включении DMA потребление тока резко возрастает, вызывая сброс платы из-за нехватки питания (особенно при питании только от USB).
5. **Скрытые ошибки**: Драйвер `esp_video` вызывает `esp_restart()` при ошибках, не успевая вывести лог в UART.

## 🛠️ Как мы это решали (The Fix)
1. **Питание**: Обязательно использовать качественный USB-порт (USB 3.0) или внешнее питание 5V (2A).
2. **menuconfig**:
   - Отключить `Brownout Detector` (для тестов).
   - Включить `Enable PSRAM DMA mode by default`.
   - Установить `Panic handler behaviour` -> `Print registers and halt` (чтобы видеть ошибки, а не ребутаться).
3. **Код (`frame_cap_pipeline.cpp`)**:
   - Явно указывать пины SCCB (I2C) и DVP.
   - Указать **3 буфера**.
   - Использовать формат `V4L2_PIX_FMT_RGB565X`.
   - Добавить отладочные метки через `esp_rom_printf`, чтобы видеть точное место падения до перезагрузки.

## 📉 Результат
Мы заставили драйвер `esp_video` инициализироваться и запустить поток (`DVP controller created OK`, `ret=0`), но при разрешении 800x600 шина захлебывается на первом же кадре. ESP32-S3 физически не тянет такой поток для нейросети.

**Решение**: Замена камеры на **OV2640** и использование разрешения **QVGA (320x240)**, либо переход на старый драйвер `esp32-camera`.

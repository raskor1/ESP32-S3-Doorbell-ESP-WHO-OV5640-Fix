# Умный домофон на ESP32-P4 + ESP32-S3

Этот репозиторий содержит код, утилиты и историю разработки автономного умного домофона с распознаванием лиц. Проект состоит из двух плат, работающих в локальной Wi-Fi сети без выхода в интернет.

## 🏗 Архитектура проекта

### 1. Монитор (Дом) — ESP32-P4 (Guition JC1060P470C)
- **Экран:** 7-дюймовый, 1024x600, LVGL 8.4.
- **Сеть:** Создает точку доступа Wi-Fi (SoftAP).
- **Видео:** Принимает видеопоток (MJPEG) с уличной камеры.
- **Управление:** Управляет реле замка (открытие с экрана или через веб-сервер).
- **Интерфейс:** Плавающие часы, интерфейс звонка, таймеры бездействия.
- **Логирование:** Ведет журнал событий на SD-карту (`/sdcard/doorbell.log`), который можно посмотреть с телефона по адресу `http://192.168.4.1/logs`.
- *Код находится в папке `01_P4_Monitor`.*

### 2. Камера (Улица) — ESP32-S3 N16R8 CAM
- **Камера:** OV5640 (DVP интерфейс).
- **Сеть:** Подключается к сети P4 как клиент (статический IP 192.168.4.2).
- **Видео:** Отдает видеопоток по HTTP (MJPEG) на порт 81.
- *Код находится в папке `02_S3_Camera_Stream`.*

## 🖼 Как добавить свои фотографии в слайд-шоу

Последняя версия прошивки для ESP32-P4 умеет показывать ваши фотографии на главном экране в качестве фона. Так как плата не может распаковывать JPG/PNG в фоне, картинки нужно заранее перевести в «сырой» формат **RGB565 (1024x600)**.

Для этого в корне репозитория лежат две утилиты: `convert.py` и `fotoredactor.bat`.

**Инструкция:**
1. Скачайте эти утилиты и положите их в одну папку.
2. Закиньте в эту же папку любые фотографии (JPG, PNG), которые хотите видеть на экране.
3. Запустите `fotoredactor.bat` (или введите `python convert.py` в консоли).
4. Скрипт автоматически обрежет фото под пропорции экрана и переконвертирует их в файлы `.rgb` в папке `images_out`.
5. Скопируйте эти файлы на вашу SD-карту в папку **`/images/`** (папка должна быть строго в корне карты).
6. Вставьте карту в плату и перезагрузите её. Фотографии будут плавно сменять друг друга каждые 4 секунды!

## 🛑 Проблема с распознаванием лиц (ESP-WHO + OV5640)

Изначально планировалось запустить распознавание лиц (ESP-WHO) прямо на уличной камере (ESP32-S3). Однако мы столкнулись с серьезными аппаратными ограничениями:

1. **Разрешение 800x600**: Драйвер `esp_video` поддерживает OV5640 на DVP-интерфейсе только в разрешении 800x600 (SVGA). Меньших разрешений (640x480 или 320x240) в `menuconfig` просто нет.
2. **Нехватка памяти и переполнение шины**: Кадр 800x600 в RGB565 занимает ~960 КБ. При попытке выделить несколько буферов для DMA (минимум 3 для ESP-WHO) память забивается, а пропускной способности шины не хватает для потока.
3. **Ошибка `ringbuf_len >= 1`**: В ESP-WHO жестко зашито, что количество буферов камеры (`fb_count`) должно быть **минимум 3**. Установка значений 1 или 2 вызывает `assert` и падение.
4. **Brownout (Просадка питания)**: При старте камеры и включении DMA потребление тока резко возрастает, вызывая сброс платы из-за нехватки питания.
5. **Скрытые ошибки**: Драйвер `esp_video` вызывает `esp_restart()` при ошибках, не успевая вывести лог в UART (бесконечная перезагрузка `rst:0xc (RTC_SW_CPU_RST)`).

### 💡 Решение
Замена камеры на **OV2640**, которая поддерживает разрешение **QVGA (320x240)**. Это снижает вес кадра в 9 раз, избавляет от проблем с DMA и позволяет комфортно запустить нейросеть.

## ⚙️ Критически важные настройки конфигурации (menuconfig)

Чтобы проект собрался и работал стабильно, необходимо внести следующие изменения:

### Для ESP32-S3 (Уличная камера, ESP-IDF v5.5.6 / v6.0)
*   **PSRAM:** Включена (`Support for external, SPI-connected RAM`), режим **Octal Mode PSRAM**, скорость 80 MHz.
*   **Flash:** 16 MB, режим DIO (не OPI, иначе плата уйдет в перезагрузку).
*   **Camera configuration:** Включен драйвер OV5640 (`Support OV5640 5MP`), интерфейс **DVP**.
*   **ESP-Video Configuration:** Включен `Enable PSRAM DMA mode by default` (критически важно!) и выбран формат `DVP 8-bit, 24M input, 800x600 10fps, RGB565(BE)`.
*   **ESP System Settings:** `Brownout Detector` — **выключен** (для тестов), `Panic handler behaviour` — `Print registers and halt`, `Invoke panic handler on Task Watchdog timeout` — включено.
*   **Костыль для GCC 15.2 (ESP-IDF v6.0):** В файле `main/CMakeLists.txt` добавлен флаг `-fno-if-conversion` для компонента `lvgl` (компилятор падал в Segmentation Fault).

### Для ESP32-P4 (Монитор, ESP-IDF v5.4.4)
*   **PSRAM:** Включена.
*   **Тайминги дисплея (JD9165):** `hbp 160, hpw 40, hfp 160, vbp 23, vpw 10, vfp 12`, частота `52 МГц` (иначе будут цветные полосы).
*   **SD-карта:** Слот 0, 4-битный режим, питание через LDO 4.

## 🛠 Используемые технологии
- **ESP-IDF v5.4.4** (для P4) и **v5.5.6 / v6.0** (для S3).
- **LVGL 8.4** (графика на P4).
- **esp32-camera / esp_video** (работа с сенсорами).
- **HTTP/MJPEG** (передача видео).
- **Python (Pillow)** (конвертация фото для SD-карты).
- **ESP-WHO / ESP-DL** (попытка интеграции нейросетей).


## 🚀 Обновление: Слайд-шоу, Логи и UI

Мы прокачали проект:
1. **Слайд-шоу на главном экране**: Теперь вместо скучного фона на часах крутятся личные фотографии (конвертируются в RGB565 скриптом на Python).
2. **Веб-логирование**: Все события (нажатия кнопок, открытие двери) пишутся в файл `doorbell.log` на SD-карту. Посмотреть их можно с телефона по адресу `http://192.168.4.1/logs`.
3. **Живые кнопки**: Прозрачные кнопки в интерфейсе теперь подсвечиваются синим при нажатии, чтобы был тактильный отклик.
